# Controller runtime

Python 3.11+ standard library only. The version-one roadmap interfaces separate
profiles, policy, execution, source inventory, evidence, native observations,
knowledge and review. `roadmap_project` adapts the registered canonical record
through one existing transaction owner. Shared atomic writes, process supervision,
confinement, locks and recovery remain their existing implementations.

`python -B bin/agentctl.py roadmap profile Aegis` describes the actual record owner.
`interfaces audit` and `interfaces compare --baseline-ref COMMIT` emit source-bound
structural observations without importing the target modules or starting inference.
See [interface contracts](../Roadmaps/Shared/INTERFACES.md).

The preserved Destiny dispatcher still owns its original plans, context and receipt
lineage; `formal.py` binds its public contracts and exact verifier observations.
New roadmap command families do not reinterpret old evidence. Python/Rust proposals
cover every maintained body under their declared roots; they supply no Rust
implementation or proof credit.

`python scripts/selftest.py` exercises operational regressions. Formal control invariants
and their deductive proof entry point are in `verification/`; their scope is narrower than
Python implementation correctness and is documented there.

`roadmap run NAME --milestone ID` uses `roadmap_work` to bind complete semantic inputs, reserve before deterministic execution, retain native and child handles, and reuse current successful results. `budget metrics/recover/reservation` expose the same existing ledger. `roadmap_acceptance` assembles implementation gates from actual results plus scoped source review; full proof, installed artifacts and final release have separate gates. See [operating procedures](../Roadmaps/Shared/OPERATIONS.md).

Native integration uses `roadmap_protocol` for exact installed schema identities and `roadmap_native_adapter` for observed Goal/Plan bindings, bounded read RPCs, public notification reduction and authorized host-callback reconciliation. A completed native Plan must match its adopted source bytes. Native control journals and tool work share the existing budget ledger; current qualification is produced by the fixed `native.protocol` and `native.acceptance` recipes.

`NativeGoalAdapter.dispatch_managed` adds the installed stdio Goal sender under that same policy and ledger. Actual server handles and replies are saved before readback, and uncertain outcomes require recovery without redispatch. `roadmap_managed.ManagedTurnRunner` provides sequential turns on an explicitly adopted existing chat with the same lease, policy and ledger. Process fixtures do not qualify live Goal mutations or managed inference; those remain explicit A04 acceptance responsibilities.
