# Operating the roadmap package

Run commands from the Aegis root. Read-only commands do not start a project Goal or model turn. Runtime projections and reservations live under `.aegis`; maintained contracts live under `Roadmaps`.

```bash
python -B bin/agentctl.py roadmap compile
python -B bin/agentctl.py roadmap audit
python -B bin/agentctl.py roadmap packet A00
python -B bin/agentctl.py skills validate
python -B bin/agentctl.py portability check
python -B scripts/validate_roadmaps.py
python -B -m unittest discover -s infra/tests -p 'test_roadmap*.py' -q
```

`roadmap compile` emits a deterministic graph. `--save` writes its projection under `.aegis`. `roadmap audit --evidence FILE` evaluates current source-bound receipts; without evidence it grants no milestone credit. `roadmap packet ID` returns one bounded contract with complete requirements and current dependency blockers. Oversized packets fail; split work without truncating obligations.

`roadmap inventory --remote --save` reads live origin heads, every local/tracking ref, each distinct tree, every Python component blob and the current working files. It retains source authority hashes, all requirement dispositions, dirty file bytes by hash, reference checkout identities and nested dirty work. Historical bodies receive structural inspection and remain pending semantic review before reuse. Collection has a finite ten-minute budget and rejects changed inputs or incomplete command output. Saving transactionally updates the registered `.aegis/project.json` record and a content-addressed snapshot; existing record fields and historical snapshots survive. `roadmap reconcile --inventory PATH` reproduces the entire snapshot and rejects missing remote refs, omitted responsibilities and changed source bytes. These commands grant source inventory evidence, with no domain proof or branch-wide semantic acceptance.

`roadmap run NAME --milestone ID` materializes a source-owned specification for an adopted Aegis work unit, records its typed `WorkUnit` in the existing canonical record, reserves through `BudgetLedger`, and executes through the existing process supervisor. Aegis qualifies the fixed local validation recipes plus `production.build`, `original.tests` and `source.reconcile`. Other project/proof/release specifications require their own qualification. Retrieved instructions and JSON cannot supply executable argv. An unscoped fixed validation remains available only where no canonical execution has been adopted.

For an adopted Aegis execution, name the canonical current milestone, for example `roadmap run production.build --milestone A03`. The scope must match the canonical record's current work unit, active native Goal identity and live fenced owner. The stable reservation identity includes the native chat and milestone. Legacy unscoped attempts within the current work unit's observed lifetime are inherited; earlier units and authoring runs remain historical. Bootstrap A00 can use the original native Goal creation boundary. Later units require their explicit `started_ns`; restarting the process does not erase already inherited ancestry. Inheritance retains successes, failures, unresolved reservations and spent time, and cannot restore an exhausted attempt allowance. A corrected retry still requires a diagnosis and changed inputs. Before reservation and immediately before dispatch, the runner observes the actual native Goal, current turn configuration and native process relationship. Active Goal, default execution mode, the selected model, effective max reasoning and the fenced owner are required. The native journal supplies metadata only; conversation contents are not copied. This active-host path starts deterministic child processes; A04 owns managed model dispatch and completed native Plan binding.

`roadmap project --record PATH --expected-digest HASH --evidence FILE` transactionally adds a projection to an existing canonical JSON record, preserving its other fields. It uses a compare-and-swap on the current bytes and the existing transaction/recovery implementation. It does not create a competing queue. Project adapters must resolve the target profile's actual canonical path and writer ownership before production adoption.

Aegis's registered record is now routed through `ProjectAdapter` and one shared transaction owner, including absolute and normalized path spellings. Inventory, projection and execution bookkeeping must use that adapter. A changed writer or unknown record version requires explicit lineage reconciliation. External project profiles remain read-only until their own actual writer is adopted. Use `roadmap profile Aegis`, `interfaces audit`, and `interfaces compare --baseline-ref COMMIT` to inspect the typed boundaries and structural compatibility; see [interfaces](INTERFACES.md). Structural observations do not replace original tests or domain verification.

`policy explain ACTION --context FILE` returns allowed/rejected reasons. The context includes active native state, execute/plan mode, provider, selected model/effective effort, exact current inputs, lease and authorization. An allowed decision describes those observations; it is not a substitute for a dispatch-time recheck.

`codex inspect` starts a bounded read-only app-server process, records executable/version/model capabilities and exits. It performs no inference, creates no chat and changes no Goal. `codex bind --observation FILE --thread ID --objective TEXT --contract HASH` binds a matching native observation without replacing its objective. `codex plan --item FILE --milestones A00,A01` binds a completed native plan item. `codex transition --current FILE --request FILE` prepares a lifecycle request only after explicit authorization fields and acceptance are checked; it does not secretly send a mutation. The active host remains responsible for supported lifecycle execution and reconciliation. A04 owns full managed dispatch and completed native Plan qualification. `codex owner` observes the active host without resuming the chat. An observer-local `notLoaded` status never establishes idleness. Qualified Goal bindings require a live native termination observation before lease release; a caller-provided terminal label cannot release an active or auto-continuing Goal.

`verification audit --obligation FILE --result FILE` reports why a proof result cannot receive credit. `review render --packet FILE --output PATH` renders deterministic HTML; source text is escaped and no scripts are loaded. `review decision` validates scope and packet freshness. `review findings` deduplicates attributed findings. The stage API requires separate campaign authorization; use owned fixtures to validate it now.

`budget status` reads the durable ledger. `budget metrics` emits a compact projection of attempts, retained allocations, measured tool microseconds, unknown measurements, reuse consumers and separate native usage series. `budget observe --thread ID --event ID --total N` merges cumulative Goal tokens; omit total to record unknown. The active-host runner also reconciles native session input, cached input, cache-write input, output, reasoning output and total categories with journal byte-offset/hash provenance. Duplicate snapshots are not added; decreases and conflicting events fail. Cached input remains a subset of input and reasoning output a subset of output. Goal and session series remain distinct. CI time, storage, prices and billing remain unknown when unobserved. A requested monetary cap blocks dependent execution because this path cannot enforce billing. No token budget is invented. `budget reservation --attempt ID` exposes the typed quota record: consumed allocation is irrevocably charged seconds, separate from measured runtime.

`knowledge get --source ID --start N --end N` returns an exact bounded text range with the original file hash. Missing extraction, invalid citations, changed versions and over-budget ranges fail. Retrieved text is data, not authority. `portability build` regenerates AST inventory and per-file Rust migration proposals; `portability check` rejects any changed or missing maintained Python unit. Generated descriptions need semantic refinement before a future Rust replacement can receive correspondence credit.

## Native Goal and Plan qualification

The current A04 work implements host/read binding, callback controls and a managed Goal lifecycle sender. The managed model-turn lifecycle remains required implementation work. Live Goal writes are unqualified until an explicitly authorized action is exercised; the read snapshot distinguishes implemented bodies from live qualification. A04 remains open, and passing the recipes below does not supply its missing implemented-output receipt.


A04 adds two fixed recipes: `roadmap run native.protocol --milestone A04` exports the complete installed app-server JSON Schema bundle, and `roadmap run native.acceptance --milestone A04` exercises the real read transport against the adopted Goal and completed Plan source. The schema manifest binds the executable, every exported JSON file, its namespace, and embedded `ThreadItem`/`Turn` definitions. Historical `codex-capabilities.json` and protocol files remain historical; current canonical bindings identify the observed installed version. An exported method is a capability contract, with actual RPC observations recorded separately.

Set the canonical execution's `native_plan_source` to the actual source thread, completed turn, item ID, text digest and adopted-source file binding. The named producer reads that persisted final native Plan through bounded item pagination and requires its UTF-8 bytes to equal the maintained adopted authority. Step lists and plan deltas cannot supply a final Plan item. The source chat may be the earlier roadmap-planning chat; it must belong to the same workspace. The current native Goal retains its own thread, objective, creation identity and cumulative accounting. Binding the Plan does not create, resume or activate another chat.

`roadmap_native_adapter.NativeRpc` permits only pinned metadata/history reads. Actual requests/replies retain contract bindings and digests; explicit RPC errors, transport uncertainty, invalid replies and policy refusals remain distinct. It never copies reasoning payloads or arbitrary tool output into acceptance records. Native model, max-effort and mode observations come from the real active host's turn configuration. The capability snapshot identifies that observation boundary. The read-only observer does not subscribe to a managed inference stream, and the adapter does not launch managed inference. Public turn/item/usage/routing notification reduction is runtime tested; a model reroute refuses further qualified use.

The acceptance producer keeps Python's HOME isolated and passes the existing Codex state location unchanged through `CODEX_HOME`. Its native state route, selected model, Plan source and binary identity are part of the semantic specification. Credential values are neither read nor copied by the producer. The actual native service still owns authentication and its internal state.

`NativeGoalAdapter.prepare` uses a current native Goal read and the same phase-aware policy for every host callback. Requests never resend objective text. Native Goal creation identity and cumulative usage cannot reset. Budget requests preserve the installed native `int64` domain and require an explicit positive value; no budget is invented. Completion requires the full adopted scope's current acceptance and all required domain obligations when that scope includes domain closure. A green status projection or a `PROVED` marker cannot omit those obligations.

`NativeGoalAdapter.dispatch` requires explicit host authorization, its stable user/control-event ID and an identified Codex host callback. It persists preparation and a reservation before invoking that callback and reconciles the actual native state afterward. These control reservations share the existing ledger. Authorized pause/clear/budget controls can be recorded during existing tool work; they do not dispatch another model. Plan mode continues to forbid production work, while explicit user pause remains available. Resume and automatic completion require the owned execution mode, selected model and max reasoning. A callback timeout leaves its native handle/reservation unresolved. `NativeGoalAdapter.recover` reobserves that same Goal without redispatching. Actual service/journal/host-callback provenance is an explicit trust boundary. Live Goal mutations are not credited by read-transport acceptance; they remain identified host lifecycle capabilities.

`NativeGoalAdapter.dispatch_managed` sends the same freshly audited lifecycle request over the pinned installed stdio server. It reserves before starting that server, records its actual process creation identity before initialization, and verifies the loaded executable through Linux `/proc`. The private client admits one prepared Goal set/clear request, forbids objective text and exposes no thread-resume or model-turn methods. It reobserves the same Goal immediately before sending. The native protocol has no conditional-write parameter; cooperating clients must respect the workspace lease, and noncooperating clients remain outside this ownership boundary.

Both dispatch paths preserve an immutable reply before readback. Explicit RPC rejection is a failed control; a missing or malformed reply may still be resolved by authoritative readback of the same Goal. A readback failure retains the reply and the uncertain reservation. Managed controls also retain their reservation while their actual server process is live or unknown. Recovery reads the original preparation, reply and native state without resending the request. Process-backed fixtures exercise these paths without changing live Goals or starting inference; they establish runtime behavior, not live native mutation qualification or domain proof.

The implementation assembler runs every named check required by the selected responsibilities, including native qualification checks inherited by later consumers. Selection preserves previously accepted responsibilities and the current milestone's dependency closure, so an unrelated blocked milestone does not prevent ready independent work. Historical projection state chooses the review denominator and grants no current acceptance. Each selected output/unit still needs current artifacts, passing tests, actual recipe receipts and the normal evidence audit. A source/review/run-bound generation directory permits additional same-candidate reviews and later source reconciliation while retaining all prior immutable acceptance bundles.

## Durable operation identities and evidence

The materialized identity binds the entire compiled source namespace, maintained Python files, exact target/argv/selection, toolchain executable and standard-library bytes, configuration, isolated environment and finite limits. Source reconciliation also binds every current branch/ref/worktree/remote-head observation. A matching successful result is reused only while its bound artifacts and semantic inputs remain current. Reuse adds a consumer without a second attempt, subprocess or usage charge. Failed/interrupted ancestry and spent allocations survive process restart and alternate work names; retry requires diagnosis and changed relevant inputs. A different source/target generation can explicitly supersede the latest successful operation only after its immutable specification, supervisor result and artifacts validate. The new generation retains every prior attempt and allocation. Failed or interrupted work cannot open a new allowance by changing its generation label; the original unscoped reservation API keeps its existing cumulative limit semantics.

A reservation records the runner creation identity before dispatch and the actual child creation identity/process group when the existing supervisor starts it. Any unresolved workspace reservation blocks another dispatch. `budget recover --attempt ID` reobserves those same handles. Live/unknown children, surviving descendants, reused group IDs and a missing child observation retain the reservation. Verified gone processes/groups can be reconciled as interrupted; a complete current supervisor result and receipt can be recovered without executing again. A different recorded local boot establishes that its old processes ended; recovery never signals a numeric group from that boot.

After a native process restart, first reconcile all operation handles. `codex rebind-process --pid PID` can then fence the same active Goal under its new native executable, provided the old creation identity is gone, the caller descends from the new process, native identity/configuration agree, and accounting has not decreased. Lease and canonical-record replacement are one existing `FileTransaction`; the generation increases and old owner/observation remain in history. Live, unknown or different native ownership is rejected. Linux `/proc` currently qualifies active-host ancestry/executable observation; other hosts retain explicit future adapter acceptance.

`roadmap accept-implementation --through ID --review PATH` assembles the initial implementation gates from successful current ledger runs, unchanged original-test sources, complete test outcomes, structural compatibility, complete Python/Rust proposals and a source-bound review covering every ancestor output/unit. The review supplies current artifact bindings, exact passing runtime test IDs and rationale. It is an explicit source-review trust boundary. The assembler preserves prior evidence, pending proof obligations and the full native objective. It cannot confer domain proof, installed-artifact acceptance, packaging, release or native Goal completion. Build/test/source execution and immutable result capture are maintained code, so later milestones reuse the same producers.

## Adoption and recovery

1. Inspect native Goal state, actual branch, dirty work, current queue generation and live operation handles. Preserve user pauses, cancellations and limits.
2. Compile the complete source/amendment set. Review the diff against the previously adopted contract; scope changes require an authorized lineage amendment.
3. Reconcile existing receipts by exact source/target/tool/configuration identity. Preserve stale evidence as historical; never silently credit it.
4. Select one dependency-ready work unit. Claim writer ownership and the workspace lease, establish effective max reasoning, reserve resources, and then dispatch.
5. On interruption, inspect actual processes/sessions before takeover. Recover pending file transactions. Retain consumed attempts and ambiguous reservations; do not refund by deleting state.
6. Recompute readiness from receipts. Commit queue, continuation and evidence coherently. Preserve all unresolved obligations and continue independent ready work.
7. Before publication, validate the exact candidate and integrated remote content. Report local commit, push, integration, deployed governance and visible checkout separately.
8. Before native completion, audit the entire adopted objective. A rejected/unknown transition is not completion; read native state back. Use the live host tool contract for blocked thresholds and user-controlled transitions.

Rollback restores the last committed record generation through the existing transaction journal. Preserve failed receipts and spent budgets. Revert only owned changes after checking intervening edits. Do not reset branches, overwrite source references, modify main, or use an old release to erase new user authorization.

## Package delivery versus product completion

This package can pass its compiler/runtime/document validation while all product milestones remain uncredited. The final delivery report must name that distinction. A09 backend qualification, A04 managed dispatch, complete corpus ingestion, Carbon implementation/proof work, CI deployment and release acceptance each require their own actual receipts. A03 active-host observations and process recovery remain local service/journal trust boundaries and cannot control noncooperating model sessions. A roadmap contract specifying work is not evidence that the work ran.

`roadmap refresh-dependencies --work ID --review PATH` refreshes current evidence for retained accepted dependencies while keeping the current implementation open. Its review must list the unfinished current responsibilities. It does not emit an implemented-output receipt for that current milestone. Use it for incremental, validated publication while a required integration path is still being built.
